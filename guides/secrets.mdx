AINode keeps credentials in a local **Secrets store** at `~/.ainode/secrets.json`
(file mode `0600`). Values are XOR-obfuscated against a per-host machine id at rest —
enough to keep tokens out of casual `cat` output, **not** real encryption. Secrets
never appear in API responses: the UI only ever shows a masked value (a short prefix
hint plus the last 4 characters). Set them in **Config → Secrets**.

## Hugging Face: read vs write

There are two HF token slots, and the difference matters:

| Slot | Used for | Required scope |
|---|---|---|
| **HuggingFace Token (read)** | Download gated models (Llama, Gemma, …) | `read` is enough |
| **HuggingFace Token (write)** | **Push** quantized / fine-tuned models to the Hub | `write` (or a write-scoped fine-grained token) |

AINode prefers the **write** token for pushes and falls back to the read token only
if it happens to carry write scope. A read-only token is **rejected up front** —
before any multi-GB upload starts — so you never wait through a transfer that ends in
a `403`.

Each HF token has a **Test** button (`GET /api/secrets/{key}/test`) that calls HF
`whoami` and reports the detected scope — `read-only`, `write`, or `fine-grained` —
plus the token identity, **without ever revealing the value**. The other credentials
below store without a live test.

<Tip>
Keep your everyday downloads on a `read` token and add a separate `write` token only
when you intend to push models back to the Hub.
</Tip>

### Setting the read token from the CLI

```bash
ainode config --hf-token hf_xxxxxxxxxxxxxxxx   # set
ainode config --hf-token ""                    # clear
```

This populates the read slot and propagates automatically to gated-model downloads
and training jobs. The write token is set in the **Secrets** UI.

## Other supported credentials

| Secret | Purpose |
|---|---|
| **NVIDIA NGC API Key** | Pull NGC-hosted models and containers |
| **Weights & Biases API Key** | Stream training metrics to W&B |
| **OpenAI API Key** | Benchmark comparisons against hosted OpenAI models |

## API

```bash
# List all known secrets — MASKED (values never returned)
curl http://localhost:3000/api/secrets

# Set a secret
curl -X PUT http://localhost:3000/api/secrets/huggingface_write_token \
  -H 'Content-Type: application/json' \
  -d '{"value": "hf_xxxxxxxxxxxxxxxx"}'

# Test an HF token's scope (never echoes the value)
curl http://localhost:3000/api/secrets/huggingface_token/test

# Delete a secret
curl -X DELETE http://localhost:3000/api/secrets/openai_api_key
```

Known keys are `huggingface_token`, `huggingface_write_token`, `nvidia_ngc_key`,
`wandb_api_key`, and `openai_api_key`. Free-form custom secrets live under
`/api/secrets/custom/{name}`. Setting an unknown key returns `400`.

## Where pushes land

When you push a quantized or fine-tuned model, AINode creates a **private** repo
under the write token's namespace (`<your-namespace>/<repo-name>`). See
[Quantize a Model](/guides/quantize) for the push workflow.

<Info>
The secrets store, HF read/write split, and scope-checked Test are current as of
**0.5.2**.
</Info>
