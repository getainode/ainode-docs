AINode quantizes models **on your own GPU**: no external service, no notebook. A
quant job runs `llm-compressor` one-shot PTQ inside a **spawned GPU container** and
writes a compressed-tensors checkpoint that vLLM serves natively.

<Note>
The shipped orchestrator image is intentionally slim (no `torch`), so, exactly
like training, a quant job runs in a GPU container spawned from the quant image
(`--gpus all`, single node, single GPU). Your model store is mounted **read-write**
so the runner reads the base weights and writes the output back into
`~/.ainode/models/`. Cancelling the job tears down the container.
</Note>

<Warning>
**The quant image is built locally.** The job runs in `ainode-quant:0.17.0-t5`,
built from `scripts/Dockerfile.quant` in the product repo. CI does not build it
and no registry carries it, so build it once on the node (on an aarch64 GB10,
where the base engine image is already pulled):

```bash
git clone https://github.com/getainode/ainode && cd ainode
docker build -f scripts/Dockerfile.quant -t ainode-quant:0.17.0-t5 .
```

A submit on a node without the image answers 400 with that build command.
`AINODE_QUANT_IMAGE` points the job at an image the node already has.
</Warning>

## Run a quantization

Open **Training → Quantize a Model**.

<Steps>
  <Step title="Base model">
    A Hugging Face repo id (`Qwen/Qwen3.5-4B`) or a model already in **Installed**.
    An on-disk copy is used automatically when present (offline + reproducible).
  </Step>
  <Step title="Scheme">
    - **AWQ**: W4A16, 4-bit weights (asymmetric, via `AWQModifier`). Serves as
      `awq_marlin` on GB10.
    - **NVFP4**: Blackwell-native 4-bit float (via `QuantizationModifier`). On the
      pinned default engine image AINode applies a MARLIN engine env for it;
      recipes on `vllm/vllm-openai:v0.27.1` serve NVFP4 without it.
  </Step>
  <Step title="Calibration samples">
    Default **256**, drawn from `HuggingFaceH4/ultrachat_200k`. More samples
    means better calibration and a longer job.
  </Step>
  <Step title="Push to Hugging Face (optional)">
    Tick **Push result to Hugging Face** and (optionally) name the repo. Requires a
    **write** token (see [Tokens & Secrets](/guides/secrets)). Write scope is
    validated **before** the job runs, so a read-only token fails fast (`400`)
    instead of after a multi-GB compute. The push happens after the job finishes and
    creates a **private** repo under your token's namespace.
  </Step>
</Steps>

<Warning>
The target node must be **idle**. Quantization needs the node's full unified memory,
so AINode refuses to start a quant job while a model is loaded on that node: **unload
all models on the node first** (or resubmit with `force: true`). You get a `409`
otherwise.
</Warning>

When the job finishes, the result appears in **Installed** as `<org--name>-<scheme>`
(e.g. `Qwen--Qwen3.5-4B-awq`), ready to launch.

## Multimodal & hybrid models (Qwen3.5)

Qwen3.5 models bundle a vision tower and use Gated-DeltaNet linear attention. AINode
handles this automatically: it loads the full model class so the saved config is
complete (vLLM-servable), keeps the vision tower, embeddings, `lm_head` and the
`linear_attn` projections in bf16, and saves the image processor.

<Note>
Quantization jobs have **no bench record** yet: the feature exists and runs, but
nothing an AINode quant job produced has been measured. What is measured is
*serving* vendor NVFP4 checkpoints on GB10: Qwen3.8 27B NVFP4 (dense), Ornith
1.5 35B-A3B NVFP4 and Nemotron 3.5 Lightning NVFP4 (MoE), all on
[Tested Models](/guides/tested-models). No AWQ catalog entry has a record.
</Note>

## Serving a quantized model

You don't hand-edit quantization flags. AINode reads the on-disk `config.json` and
picks the right kernel path automatically:

- **AWQ** serves as `awq_marlin` on GB10 (sm121).
- **NVFP4** serves natively on `vllm/vllm-openai:v0.27.1` recipes; on the pinned
  default engine image AINode applies a MARLIN engine env when the config
  reports NVFP4 quantization.

A per-load `quantization` override is honored if you ever need to force it. See
[Troubleshooting: Quantized models on GB10](/troubleshooting).

## API

```bash
# Start a quant job (idle node required)
curl -X POST http://localhost:3000/api/training/jobs \
  -H 'Content-Type: application/json' \
  -d '{
        "method": "quantize",
        "base_model": "Qwen/Qwen3.5-4B",
        "scheme": "awq",
        "calib_samples": 256,
        "push_to_hf": false
      }'

# Poll status / progress
curl http://localhost:3000/api/training/jobs/{job_id}

# When done, the quantized model is listed in the catalog
curl http://localhost:3000/api/models | grep awq
```

To push to the Hub, add `"push_to_hf": true` (and optionally `"hf_repo": "name"`).
Write scope is asserted before the job starts, so a read-only token is rejected up
front. To override the idle-node guard, add `"force": true`.

## Why 4-bit on GB10

GB10 decode is memory-bandwidth bound. 4-bit weights mean fewer bytes read per
token, so a quantized model both **fits more easily** and **decodes faster**. The
measured NVFP4 numbers on GB10 are on [Tested Models](/guides/tested-models).
