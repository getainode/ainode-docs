## What it is

AutoData is a training **utility** (not a served product surface) that lives in
`ainode/training/autodata/`. It generates synthetic fine-tuning data by pitting a weak
and a strong model against the same tasks and keeping only the examples that sit in the
**zone of proximal development** — the ones the strong model solves and the weak model
misses.

Four roles, all reached as plain OpenAI-compatible HTTP endpoints served by your fleet:

1. **Challenger** — generates a batch of candidate tasks from your `task_spec`.
2. **Weak solver** — a small model; attempts every task.
3. **Strong solver** — a big model; attempts every task.
4. **Judge** — grades both attempts.

For each task AINode computes `Δ = I_strong − I_weak`. Only `Δ == 1` (strong solves,
weak fails) is **kept**; `Δ == 0` is too-easy/too-hard, `Δ == -1` is judge noise. Kept
examples are emitted as **ShareGPT JSONL** with a yield report.

Because it is pure HTTP with no torch, AutoData runs inside the slim shipped
orchestrator — it just needs AINode-served endpoints (point `strong` at a big model, `weak`
at a small one). It stays a synthetic-data utility: the only live product surface is the
dashboard panel. Powered by argentos.ai.

## Config

`AutoDataConfig` has a top-level `task_spec`, a `gen_prompt` (the Challenger system
prompt **P**), and four `Endpoint` blocks. Each endpoint is:

```json
{
  "url": "http://localhost:8001/v1",
  "model": "served-model-name",
  "max_tokens": 512,
  "temperature": 0.0,
  "api_key": "EMPTY",
  "timeout": 120
}
```

Other keys (all optional with the defaults shown):

| Key | Default | Meaning |
|---|---|---|
| `n_tasks` | `50` | Tasks the Challenger generates per round |
| `system_prompt` | `""` | System message for solvers, also emitted with kept data |
| `judge_mode` | `"rubric"` | `rubric` (LLM), `verify` (math/numeric, rubric fallback), or `exact` (substring) |
| `concurrency` | `8` | Parallel task workers |
| `retries` | `2` | Transient HTTP/parse retries per model call |
| `out` | `""` | JSONL output path |

## Running it

```bash
python -m ainode.training.autodata.run --config cfg.json
```

To close the loop, add the **meta-optimizer**, which rewrites the Challenger prompt each
round toward the target:

```bash
python -m ainode.training.autodata.run --config cfg.json --meta --objective valset
```

Meta flags: `--meta`, `--objective yield|valset`, `--target-yield`, `--target`,
`--max-rounds` (default `4`). The v2.1 history-aware meta-optimizer and the dashboard
panel are both shipped.

## The v2.2 val-set objective

The default `yield` objective optimizes the per-batch `Δ=1` keep-rate — a noisy,
self-graded proxy that re-samples fresh tasks every round. The `valset` objective
replaces it with a **held-out, ground-truth-graded lift** signal:

```
lift(P) = acc(weak | few-shot of kept D(P)) − acc(weak alone)   # on a FIXED, GT-labeled val set
```

The weak solver is scored on a fixed, GT-labeled `val_set` twice: cold (baseline,
computed once) and primed with a `val_shots`-example sample of the round's kept traces —
both graded by the **same trusted verifier** the Δ-filter uses. This is in-context
learning used as a torch-free proxy for fine-tuning lift: if the kept traces teach,
showing a few raises verified val accuracy. Because the val set is fixed and GT-graded,
the reward is stable and comparable round-over-round.

Config keys for the objective:

| Key | Default | Meaning |
|---|---|---|
| `objective` | `"yield"` | `yield` (v2.1 proxy) or `valset` (v2.2 lift) |
| `val_set` | `[]` | Held-out probes `[{"input", "reference"}]` |
| `val_shots` | `3` | Few-shot examples (from kept) used to prime the weak solver |
| `val_target` | `0.10` | Stop-threshold (absolute lift) |
| `alpha` | `0.05` | Significance level for the paired (McNemar) lift test |
| `val_min_n` | `12` | Minimum val-set size before a lift can be accepted as real |

A lift is only **accepted** (and only early-stops the loop) when it clears a paired
exact McNemar test at `alpha` **and** the val set has at least `val_min_n` probes.
Enable with `--meta --objective valset`.

## Live results

First live `--objective valset` run on AINode-served models — 2026-07-06, 4-node GB10
fleet, ainode 0.5.0, executed from the spark-1 host:

| Domain | weak / strong+judge+challenger | val_set | baseline | best lift | p (exact McNemar) | yield | rounds |
|---|---|---|---|---|---|---|---|
| Math word problems | Qwen2.5-0.5B-Instruct / Nemotron-Cascade-2-30B-A3B-NVFP4 | 24 (GT-verified) | 0.500 (12/24) | **+0.458** (0.958 primed) | **0.0005** (significant) | 44% (7/16 kept) | 1 (early stop) |

The weak solver alone scored 12/24; primed with a 3-shot sample of the round's 7 kept
Δ=1 teacher traces it scored 23/24 — lift **+0.458** at **p=0.0005** on the paired exact
test, clearing the 0.15 target with significance in the first round (the loop stopped
early by design). Config: `n_tasks=16`, `val_shots=3`, `val_target=0.15`.

## Config recipe

A runnable `cfg.json` for the val-set objective. Point the endpoints at your fleet ports
(a big model as `strong`/`judge`/`challenger`, a small one as `weak`):

```json
{
  "task_spec": "Grade-school and early-algebra math word problems with a single numeric answer.",
  "gen_prompt": "You are a math problem author. Write clear, self-contained word problems that have exactly one correct numeric answer.",
  "challenger": {"url": "http://localhost:8001/v1", "model": "nemotron-cascade", "max_tokens": 6000},
  "weak":       {"url": "http://localhost:8000/v1", "model": "qwen2.5-0.5b"},
  "strong":     {"url": "http://localhost:8001/v1", "model": "nemotron-cascade", "max_tokens": 4000},
  "judge":      {"url": "http://localhost:8001/v1", "model": "nemotron-cascade"},
  "judge_mode": "verify",
  "n_tasks": 16,
  "objective": "valset",
  "val_shots": 3,
  "val_target": 0.15,
  "val_set": [
    {"input": "A baker had 24 muffins and sold 3/4 of them. How many are left?", "reference": "6"},
    {"input": "A train travels 60 miles in 1.5 hours. What is its average speed in mph?", "reference": "40"},
    {"input": "If 5 pens cost $7.50, what is the price of one pen in dollars?", "reference": "1.5"}
  ],
  "out": "autodata_math.jsonl"
}
```

<Warning>
**Reasoning-model challengers truncate at the default `max_tokens`.** A reasoning model
emitting the whole task batch as one JSON blob will hit the 512-token endpoint default
and return truncated, unparseable JSON. Set the challenger's `max_tokens` high (e.g.
`6000`).
</Warning>

## Honest limits

- The live result is a **single round**, so the prompt-rewriter path is exercised only by
  the offline demos so far.
- Lift is **in-context-learning lift** (a torch-free proxy), **not** fine-tuning lift —
  do not read it as a fine-tuning result.
- The val set was 24 probes — small, but paired and exact-tested.
- The judge and strong solver shared one model (Nemotron).
