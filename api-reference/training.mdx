## Endpoints

| Method | Path | Description |
|---|---|---|
| POST | `/api/training/jobs` | Submit a new training job |
| GET | `/api/training/jobs` | List all jobs |
| GET | `/api/training/jobs/{id}` | Job status + progress |
| DELETE | `/api/training/jobs/{id}` | Cancel a job |
| GET | `/api/training/jobs/{id}/logs` | Tail logs (`?tail=N`) |
| GET | `/api/training/jobs/{id}/output` | List output artifacts |
| GET | `/api/training/jobs/{id}/output/{file}` | Download an artifact |
| POST | `/api/training/jobs/{id}/merge` | Merge LoRA/QLoRA into base model |
| POST | `/api/training/jobs/{id}/resume` | Resume from checkpoint (not working in container mode, see below) |
| GET | `/api/training/templates` | List templates (built-in + custom) |
| POST | `/api/training/templates` | Save a custom template |
| GET | `/api/training/stats` | Aggregate counters |
| POST | `/api/training/estimate` | Memory/time estimates |
| POST | `/api/training/autodata` | Start an AutoData synthetic-data run |
| GET | `/api/training/autodata/{run_id}` | Poll an AutoData run |

<Note>
LoRA, QLoRA and full training, adapter merge and quantize jobs all run in a
spawned GPU container on this node (the slim orchestrator has no torch/peft).
The container image, `ainode-quant:0.17.0-t5` from `scripts/Dockerfile.quant`,
is **built locally on the node**; CI does not publish it. A submit on a node
without it answers **400** with the `docker build` command. Every run is single
node: there is no multi-node (DDP) path and no DPO. See
[Fine-Tuning](/guides/training).
</Note>

## Datasets

| Method | Path | Description |
|---|---|---|
| GET | `/api/datasets` | List datasets on this node |
| POST | `/api/datasets` | Create one from a body |
| POST | `/api/datasets/upload` | Upload a file (JSONL, JSON, CSV) |
| GET | `/api/datasets/{dataset_id}` | One dataset |
| GET | `/api/datasets/{dataset_id}/preview` | The first rows |
| DELETE | `/api/datasets/{dataset_id}` | Delete it |

The runner tokenizes rows shaped `{"text"}`, `{"instruction", "output"}` or
`{"prompt", "completion"}`.

## Submit a job

```bash
curl -X POST http://localhost:3000/api/training/jobs \
  -H "Content-Type: application/json" \
  -d '{
    "base_model": "Qwen/Qwen2.5-7B-Instruct",
    "dataset_path": "alpaca.jsonl",
    "method": "lora",
    "num_epochs": 3,
    "batch_size": 4,
    "lora_rank": 16,
    "eval_split": 0.1
  }'
```

Returns HTTP **201** with the job's full status object:

```json
{
  "job_id": "abc123",
  "status": "pending",
  "progress": 0.0,
  "current_epoch": 0,
  "current_loss": null,
  "start_time": null,
  "end_time": null,
  "elapsed_seconds": null,
  "config": { "base_model": "...", "method": "lora", "...": "..." }
}
```

## Training methods

`method` accepts:

| Method | Description |
|---|---|
| `lora` | LoRA fine-tune (default) |
| `qlora` | Quantized LoRA fine-tune |
| `full` | Full fine-tune, all weights, on this node's GPU |
| `quantize` | Not a fine-tune: produces a servable AWQ/NVFP4 checkpoint via llm-compressor |

## Training config fields

```json
{
  "base_model": "Qwen/Qwen2.5-7B-Instruct",
  "dataset_path": "path/or/hf-dataset-id",
  "dataset_id": "ds_abc123",
  "method": "lora",
  "num_epochs": 3,
  "batch_size": 4,
  "learning_rate": 0.0002,
  "lora_rank": 16,
  "lora_alpha": 32,
  "max_seq_length": 2048,
  "gradient_accumulation_steps": 1,
  "warmup_steps": 0,
  "weight_decay": 0.0,
  "eval_split": 0.1,
  "eval_steps": 0,
  "use_gradient_checkpointing": false,
  "attn_implementation": "eager",
  "output_dir": "my-run",
  "template_id": "chatml",
  "description": "run notes",
  "hf_token": "hf_xxx",
  "wandb_project": "my-project",
  "run_name": "alpaca-7b-run1"
}
```

<Note>
Use **either** `dataset_path` **or** `dataset_id`. `dataset_id` references a
registered dataset in the DatasetManager. `attn_implementation` defaults to
`eager` because the training image's SDPA kernels do not run on GB10 (sm121);
`auto` hands the choice to transformers. A job whose loss or gradient norm goes
non-finite fails with `AINODE_ERROR:NAN_LOSS` and saves nothing; saved weights
are scanned and a non-finite value fails the job with
`AINODE_ERROR:NAN_WEIGHTS`. A `distributed: true` submit is refused with 400.
</Note>

### Quantize-job fields (`method: "quantize"`)

```json
{
  "base_model": "Qwen/Qwen2.5-7B-Instruct",
  "method": "quantize",
  "scheme": "awq",
  "calib_dataset": "HuggingFaceH4/ultrachat_200k",
  "calib_samples": 256,
  "out_slug": "Qwen--Qwen2.5-7B-Instruct-awq",
  "push_to_hf": false,
  "hf_repo": "my-org/my-quant"
}
```

`scheme` is `awq` or `nvfp4`. A quantize submit while the node is serving a
model returns HTTP **409** unless `force: true`, because quantization needs the node's
full unified memory.

## AutoData: Δ-filtered synthetic data

AutoData is a Δ-filter synthetic-data utility (pure HTTP, no torch). A run
writes ShareGPT JSONL, registers it as a dataset, and returns a `dataset_id`.
The training runner does not tokenize the ShareGPT `conversations` shape yet,
so convert the file to `text`, `instruction`/`output` or `prompt`/`completion`
rows before training on it.

```bash
curl -X POST http://localhost:3000/api/training/autodata \
  -H "Content-Type: application/json" \
  -d '{
    "config": { "...AutoDataConfig...": "..." },
    "meta": true,
    "target_yield": 30,
    "max_rounds": 4,
    "name": "my-autodata-set",
    "description": "Δ-filtered synthetic dataset"
  }'
```

Returns HTTP **202**:

```json
{ "run_id": "a1b2c3d4e5f6", "status": "running", "poll": "/api/training/autodata/a1b2c3d4e5f6" }
```

Poll it:

```bash
curl http://localhost:3000/api/training/autodata/a1b2c3d4e5f6
```

```json
{
  "run_id": "a1b2c3d4e5f6",
  "status": "completed",
  "meta": true,
  "dataset_id": "ds_abc123",
  "report": { "kept": 420, "best_yield": 0.31, "best_lift": 0.458, "best_score": 0.71, "best_significant": true },
  "rounds": [ ],
  "out": "/.../datasets/autodata-a1b2c3d4e5f6.jsonl",
  "error": null
}
```

On completion the generated JSONL is registered as a dataset under the
returned `dataset_id`. A meta/val-set run reports `best_lift`, `best_score`,
and `best_significant`: the held-out lift objective the optimizer maximized.

## Merge LoRA adapter

```bash
curl -X POST http://localhost:3000/api/training/jobs/abc123/merge
```

Requires the source job's status to be `completed` and its method to be `lora`
or `qlora` (else 409/400). Returns HTTP **202**:

```json
{
  "merge_job_id": "def456",
  "source_job_id": "abc123",
  "adapter_dir": "/.../abc123",
  "output_dir": "/.../merged",
  "status": "running",
  "message": "Merge started. Poll GET /api/training/jobs/{merge_job_id} for status."
}
```

Poll the merge with `GET /api/training/jobs/{merge_job_id}`.

## Resume from checkpoint

<Warning>
In the shipped container mode a resume does not work: the resumed job is
handed the orchestrator's checkpoint path and the source job's directory is
not mounted into the new container, so Hugging Face raises "Can't find a valid
checkpoint" and the job fails. The endpoint is documented here because it
exists; do not build on it until that is fixed.
</Warning>

Requires the source job's status to be `failed`, `cancelled`, or `completed`
(else 409).

```bash
# Use latest checkpoint
curl -X POST http://localhost:3000/api/training/jobs/abc123/resume

# Specify a checkpoint
curl -X POST http://localhost:3000/api/training/jobs/abc123/resume \
  -d '{"checkpoint": "checkpoint-500"}'
```

Returns HTTP **201**:

```json
{
  "resume_job_id": "ghi789",
  "source_job_id": "abc123",
  "checkpoint": "checkpoint-500",
  "checkpoint_path": "/.../abc123/checkpoint-500",
  "available_checkpoints": ["checkpoint-500", "checkpoint-250"],
  "status": "pending"
}
```
